# Final pre-deployment audit — 2026-10-25

Recommendation: **NO-GO pending the remaining release gates below.** No production database mutations, new Supabase projects, merges or production deployments were performed. Draft PR #4 remains the review boundary.

## Implemented

- Event discussion/likes and admin notification modules load only when needed. First marketplace batch is 12 rather than 24; anonymous featured previews are bounded to 8. Existing Load More remains. Images in product cards continue using `_t` thumbnails, never original product photographs.
- Promotions no longer auto-advance/download unseen artwork. Further slide images receive their source only when selected or swiped into view. Manual carousel navigation remains.
- Data-saver/2G clients avoid realtime sockets and use existing query/cache refresh paths. In-flight caching now respects sign-out/invalidation and cannot overwrite a newer session cache. Storefront visits fetch current listing results.
- Service worker version `hh-v1-1-audit-1`: only same-origin static assets, bounded to 80 entries; cached artwork uses cache-first without a background redownload; fixed-name scripts/styles revalidate; navigation uses the network or an explicit offline page, never stale product HTML. External Supabase responses, `/api/`, and writes are excluded. Old workers finish existing sessions before updating, avoiding mid-session module mixing. Bump version whenever static artwork changes at the same URL.
- Lightweight offline retry page and startup import failure UI; sign-out rerenders the current route. Listing network errors are distinguished from deleted listings. Compact layout/touch-target improvements and browser checks at 320, 360, 390, 768 and 1280px.
- Reports INSERT policy in migration now prevents a reporter from forging moderation status/reviewer identity. Existing admin resolution/audit behavior stays intact.
- `.vercelignore` excludes database/test/development artifacts from hosting. No app framework or runtime dependency was added. Playwright is installed in `/tmp` in CI only.

## Database verification and security review

The disposable CI PostgreSQL 17 harness recreates the **existing public schema** from read-only catalogs: enum types, columns/generated expressions, constraints, function bodies, view definitions, triggers, policies, table grants and function execution grants. `public-schema.sql` contains schema only, no production rows. Auth UID/JWT functions and storage objects are compatibility stubs, explicitly not a full Supabase Auth/Storage deployment. Extension-specific indexes/default privileges, managed services, JWT issuance and storage authorization need separate integration checks.

CI successfully applied `db/v1_1.sql`, ran the database contract, and exercised anonymous/student/vendor/admin roles: profile privacy, no event user-ID exposure, idempotent event likes, first-name comments, rejection of draft-event likes and student admin actions, legacy approved vendor edits, normalized duplicate rejection, report insert restrictions and admin comment hiding. The suite rolls fixture transactions back. A disposable `pg_dump`/`pg_restore` rehearsal passed with a synthetic user/profile sentinel verifying row preservation in the restored database, followed by rerun contracts/roles. CI evidence: [run 40246138203](https://github.com/nosifishola-max/HikmahHub/actions/runs/40246138203).

All 42 existing public SECURITY DEFINER function definitions and effective anon/authenticated execution privileges were inspected. The advisor warnings cover two deliberate public preview views, anonymous-callable functions, 38 authenticated-callable functions and disabled leaked-password protection. Groups overlap; trigger-only functions are not public endpoints.

- Every admin mutation/report/storage/notification endpoint checks `is_admin()`. Demand opportunities checks admin or approved vendor. Ownership helpers derive ownership from `auth.uid()` and are used by RLS; vendor discard checks ownership.
- Shared product/store/event/deal functions restrict status and return allowlisted public columns. Product-like reads expose aggregate counts and the caller's own like flag. Branding version/promo next-change expose non-sensitive state. Public preview views deliberately expose approved/featured records despite signed-in-only base-table policies; invoker conversion would break anonymous previews.
- Analytics write RPCs intentionally bypass admin-only analytics table policies, derive caller identity from auth, and check target status. Search/WhatsApp require sign-in. View tracking permits anonymous use; anonymous analytics abuse/rate limiting remains an operational concern. Product view RPC checks product approval but does not also check vendor approval; review this guard before expanding public tracking.
- Internal notification/trigger helpers have no anon/authenticated EXECUTE grants. Snapshot rankings allows scheduler execution without a user and denies signed-in non-admins; anon EXECUTE is already revoked. Definer search paths are empty. No blanket invoker conversion or grant revocation was applied.
- Existing profile guard prevents users changing role/active state. Private matric values remain in owner/admin profiles and out of previews/comments.
- [Definer advisor guidance](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable). [Leaked password protection](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection) remains disabled and needs an explicitly approved configuration change. The changelog fetch/local registry access were blocked by the workspace proxy. CI registry scanning found a high-severity Nodemailer advisory in the old dependency; Nodemailer is now pinned to 10.2.1 with a registry-integrity lockfile. CI passed `npm audit --omit=dev` with zero reported vulnerabilities and an offline MIME/envelope compatibility test. This is a major dependency update; real SMTP delivery still requires verification.

## Release gates and verification limits

- Full authenticated browser journeys remain **unverified**: registration/confirmation, login/logout/token expiry, account updates, application approval email, product upload/edit/moderation, contact tracking persistence, event/report browser workflows, admin/vendor dashboards and sharing/storefronts against a full backend. SQL role tests are useful evidence but do not substitute for those journeys.
- Database migration is validated against the public-schema compatibility copy, not a full restored managed Supabase instance. Rehearse with the complete authorized schema/Auth/Storage setup before production approval.
- Actual production backup availability, retention/PITR and restore integrity have **not** been verified. Disposable backup rehearsal is not a production backup. An owner must verify a recent recoverable database backup and separately back up Storage objects before migration. Record backup ID/time, checksum, recovery point/time objectives, and prove restoration into an isolated local environment; do not proceed on a screenshot of a successful backup alone.
- Physical low-end Android, 200% zoom, screen-reader/contrast audit, warm service-worker caching/update migration from hh-v3, authenticated slow-network/retry flows and broad list pagination remain outstanding. Current event/deal lists are bounded to 40 and storefront search to 60; these are not complete pagination implementations.
- Read-only/fixture tests leave production data intact. Vendor reviews remain deferred. No fully-tested claim is made.
